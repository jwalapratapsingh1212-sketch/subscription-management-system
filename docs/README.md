## Recommended reading order

1. Start with the root [README](../README.md) for project overview and local quick start.
2. Read the [system architecture](architecture/system_architecture.md) for component responsibilities and business workflows.
3. Read [backend documentation](../backend/README.md) and [frontend documentation](../frontend/README.md) for implementation details.
4. Read [database documentation](../database/README.md) and [test documentation](../tests/README.md) before changing persistence or test behavior.

## Documentation maintenance

When adding a feature, update the relevant module documentation and the root README if the change affects setup, user-facing functionality, API behavior, security, or deployment. Distinguish implemented behavior from planned integrations. Verify commands against the current source before publishing them.
